Yes. The important distinction is that **DLL existence/symbol existence cannot produce a Rust compile-time error** if you also want the program to compile when the DLL is absent. The `required` validation therefore happens when `MyStruct::new()` runs.

This gives you:

```rust
required fn foo(...);
```

and:

```rust
fallback fallback_foo => fn foo(...);
```

where the DLL function is preferred, but the Rust fallback is used if either the DLL or symbol is unavailable.

```rust
use std::ffi::{c_void, CString};

// ============================================================
// Minimal Windows DLL loader support
// ============================================================

#[doc(hidden)]
pub struct __DllHandle(*mut c_void);

impl __DllHandle {
    pub fn load(path: &str) -> Result<Self, String> {
        let wide: Vec<u16> = path
            .encode_utf16()
            .chain(std::iter::once(0))
            .collect();

        let handle = unsafe { LoadLibraryW(wide.as_ptr()) };

        if handle.is_null() {
            Err(format!(
                "failed to load DLL {path:?}: {}",
                std::io::Error::last_os_error()
            ))
        } else {
            Ok(Self(handle))
        }
    }

    pub fn symbol(&self, name: &str) -> *mut c_void {
        let name = CString::new(name)
            .expect("DLL symbol name contained an embedded NUL");

        unsafe { GetProcAddress(self.0, name.as_ptr().cast()) }
    }
}

impl Drop for __DllHandle {
    fn drop(&mut self) {
        unsafe {
            FreeLibrary(self.0);
        }
    }
}

#[link(name = "kernel32")]
unsafe extern "system" {
    fn LoadLibraryW(name: *const u16) -> *mut c_void;
    fn GetProcAddress(
        module: *mut c_void,
        name: *const u8,
    ) -> *mut c_void;
    fn FreeLibrary(module: *mut c_void) -> i32;
}


// ============================================================
// DLL API macro
// ============================================================

macro_rules! dll_api {
    (
        $vis:vis struct $struct_name:ident($dll:expr) {
            $(
                $mode:ident $( $fallback:path => )?
                fn $name:ident(
                    $( $arg:ident : $arg_ty:ty ),* $(,)?
                ) -> $ret:ty;
            )*
        }
    ) => {
        $vis struct $struct_name {
            // Keep the DLL loaded as long as this object exists.
            __dll: Option<$crate::__DllHandle>,

            $(
                $name: Option<
                    unsafe extern "system" fn(
                        $( $arg_ty ),*
                    ) -> $ret
                >,
            )*
        }

        impl $struct_name {
            pub fn new() -> Result<Self, String> {
                // Failure to load the DLL is not immediately fatal.
                //
                // It only becomes fatal if one of the declared functions
                // is `required`.
                let (__dll, __load_error) =
                    match $crate::__DllHandle::load($dll) {
                        Ok(dll) => (Some(dll), None),
                        Err(err) => (None, Some(err)),
                    };

                $(
                    let $name:
                        Option<
                            unsafe extern "system" fn(
                                $( $arg_ty ),*
                            ) -> $ret
                        >
                        =
                        dll_api!(
                            @resolve
                            $mode $( $fallback => )?;
                            __dll.as_ref();
                            __load_error.as_deref();
                            stringify!($name);
                            ($( $arg_ty ),*) -> $ret
                        )?;
                )*

                Ok(Self {
                    __dll,
                    $( $name, )*
                })
            }

            $(
                dll_api!(
                    @method
                    $mode $( $fallback => )?;
                    fn $name(
                        $( $arg : $arg_ty ),*
                    ) -> $ret
                );
            )*
        }
    };


    // ========================================================
    // required
    // ========================================================

    (
        @resolve
        required;
        $dll:expr;
        $load_error:expr;
        $name:expr;
        ($( $arg_ty:ty ),*) -> $ret:ty
    ) => {{
        match $dll {
            Some(dll) => {
                let ptr = dll.symbol($name);

                if ptr.is_null() {
                    Err(format!(
                        "required DLL symbol {:?} was not found",
                        $name
                    ))
                } else {
                    let function:
                        unsafe extern "system" fn(
                            $( $arg_ty ),*
                        ) -> $ret
                        =
                        unsafe {
                            std::mem::transmute(ptr)
                        };

                    Ok(Some(function))
                }
            }

            None => {
                Err(
                    $load_error
                        .unwrap_or("required DLL could not be loaded")
                        .to_owned()
                )
            }
        }
    }};


    // ========================================================
    // fallback
    // ========================================================

    (
        @resolve
        fallback $fallback:path =>;
        $dll:expr;
        $load_error:expr;
        $name:expr;
        ($( $arg_ty:ty ),*) -> $ret:ty
    ) => {{
        // Suppress unused warnings.
        let _ = $load_error;
        let _ = stringify!($fallback);

        match $dll {
            Some(dll) => {
                let ptr = dll.symbol($name);

                if ptr.is_null() {
                    Ok(None)
                } else {
                    let function:
                        unsafe extern "system" fn(
                            $( $arg_ty ),*
                        ) -> $ret
                        =
                        unsafe {
                            std::mem::transmute(ptr)
                        };

                    Ok(Some(function))
                }
            }

            // DLL itself doesn't exist.
            // That's okay for fallback functions.
            None => Ok(None),
        }
    }};


    // ========================================================
    // required method
    // ========================================================

    (
        @method
        required;
        fn $name:ident(
            $( $arg:ident : $arg_ty:ty ),*
        ) -> $ret:ty
    ) => {
        pub fn $name(
            &self,
            $( $arg : $arg_ty ),*
        ) -> $ret {
            let function = self
                .$name
                .expect(
                    "required DLL symbol was validated during new()"
                );

            unsafe {
                function($( $arg ),*)
            }
        }
    };


    // ========================================================
    // fallback method
    // ========================================================

    (
        @method
        fallback $fallback:path =>;
        fn $name:ident(
            $( $arg:ident : $arg_ty:ty ),*
        ) -> $ret:ty
    ) => {
        pub fn $name(
            &self,
            $( $arg : $arg_ty ),*
        ) -> $ret {
            match self.$name {
                Some(function) => {
                    unsafe {
                        function($( $arg ),*)
                    }
                }

                None => {
                    $fallback($( $arg ),*)
                }
            }
        }
    };
}
```

Then the intended declaration is very small:

```rust
const DLL_PATH: &str = r"C:\somewhere\my.dll";

fn my_function_fallback(value: i32) -> i32 {
    value * 2
}

dll_api! {
    pub struct MyStruct(DLL_PATH) {
        required fn absolutely_required(value: i32) -> i32;

        fallback my_function_fallback =>
            fn my_function(value: i32) -> i32;
    }
}
```

And normal code doesn't care whether `my_function` came from the DLL:

```rust
let my_struct = MyStruct::new()?;

// MUST exist in the DLL, otherwise new() returned Err.
let a = my_struct.absolutely_required(10);

// DLL implementation if available.
// my_function_fallback() otherwise.
let b = my_struct.my_function(10);
```

So the resolution semantics are:

| Situation                  | `required`                | `fallback`    |
| -------------------------- | ------------------------- | ------------- |
| DLL + symbol exist         | DLL function              | DLL function  |
| DLL exists, symbol missing | `MyStruct::new()` → `Err` | Rust fallback |
| DLL missing                | `MyStruct::new()` → `Err` | Rust fallback |

One important detail: I used `extern "system"` for the DLL functions. If these are ordinary C ABI exports from your own DLL rather than Win32-style exports, change those function-pointer declarations to `extern "C"`.

Your clarified behavior is exactly how I would structure it. **The current design is close, but I would make a few changes before treating it as a reusable FFI abstraction.**

## The loading semantics I recommend

Treat the entire macro-generated struct as one native API contract:

```text
DLL/SO missing
    ├─ zero required functions  -> OK, construct using all fallbacks
    └─ >=1 required function    -> ERROR, struct cannot be constructed

DLL/SO exists
    ├─ all required symbols exist
    │      ├─ optional symbol exists -> native function
    │      └─ optional missing       -> fallback
    │
    └─ any required symbol missing -> ERROR, struct cannot be constructed
```

So this:

```rust
native_api! {
    pub struct MyStruct(LIB_PATH) {
        fallback(my_foo_fallback)
        fn my_foo(x: i32) -> i32;

        fallback(my_bar_fallback)
        fn my_bar(x: i32) -> i32;
    }
}
```

works perfectly well when `LIB_PATH` doesn't exist.

But this:

```rust
native_api! {
    pub struct MyStruct(LIB_PATH) {
        required
        fn initialize() -> i32;

        fallback(my_foo_fallback)
        fn my_foo(x: i32) -> i32;
    }
}
```

**requires the library**, because `initialize` is required.

That matches what you're describing.

# Changes I would make

### 1. Use `extern "C"`

Since these are normal C libraries, definitely change:

```rust
extern "system"
```

to:

```rust
extern "C"
```

throughout the generated function pointers.

For example:

```rust
unsafe extern "C" fn(i32) -> i32
```

That is the correct ABI abstraction for both your `.dll` and `.so` implementations.

---

### 2. Validate all `required` functions before constructing the struct

I would change the implementation slightly from what I gave you before.

Don't conceptually do:

```text
resolve foo
resolve bar
resolve baz
hit missing required symbol
return error
```

Instead initialize in three phases:

```rust
1. Load library
2. Validate ALL required symbols
3. Resolve optional/fallback symbols
4. Construct MyStruct
```

The important invariant becomes:

> **If `MyStruct` exists, every `required` function is guaranteed to exist.**

Then generated required methods don't even need to store an `Option`.

Instead of:

```rust
required_function: Option<unsafe extern "C" fn(...) -> ...>,
```

store:

```rust
required_function: unsafe extern "C" fn(...) -> ...,
```

while fallback functions remain:

```rust
optional_function: Option<unsafe extern "C" fn(...) -> ...>,
```

That's a better representation of the contract.

---

### 3. Keep the library handle inside the struct

This is **mandatory**, and the previous implementation already did it.

Never do something like:

```rust
let library = load_library(...);

let function = get_symbol(...);

drop(library);

function();
```

The function pointer may point into unloaded memory.

The generated struct should therefore look conceptually like:

```rust
pub struct MyStruct {
    library: Option<Library>,

    required_foo: unsafe extern "C" fn(...),

    optional_bar:
        Option<unsafe extern "C" fn(...)>,
}
```

For a fallback-only API with no library present:

```rust
library: None
```

is valid.

## 4. I would change the macro syntax slightly

I prefer this:

```rust
native_api! {
    pub struct MyStruct(LIB_PATH) {
        required
        fn initialize(config: *const Config) -> i32;

        fallback(my_function_fallback)
        fn my_function(value: i32) -> i32;

        fallback(other_fallback)
        fn other_function(value: f64) -> f64;
    }

```

over my previous:

```rust
fallback my_function_fallback =>
    fn my_function(...)
```

`fallback(...)` reads more like a modifier and scales better if you eventually add other properties.

You could make it one-line too:

```rust
required fn initialize() -> i32;

fallback(my_function_fallback)
fn my_function(value: i32) -> i32;
```

Or:

```rust
fallback(my_function_fallback) fn my_function(value: i32) -> i32;
```

All are straightforward for `macro_rules!`.

I would name the macro something like:

```rust
native_api!
```

or:

```rust
dynamic_api!
```

rather than `dll_api!`, since the generated abstraction doesn't actually care whether the backing file is:

```text
foo.dll
libfoo.so
libfoo.dylib
```

# One particularly important safety issue

The macro **cannot verify that the Rust function signature matches the C function signature**.

Suppose C exports:

```c
double calculate(double value);
```

but you accidentally declare:

```rust
required fn calculate(value: i32) -> i32;
```

The symbol:

```text
calculate
```

exists, so `GetProcAddress`/`dlsym` succeeds.

But calling it using the wrong signature is **undefined behavior**.

There is no runtime type information in a normal C export that lets Rust validate this.

So this declaration:

```rust
required fn calculate(value: f64) -> f64;
```

is effectively an assertion by you that the native declaration is:

```c
double calculate(double value);
```

That's probably the single biggest inherent safety limitation of this abstraction.

# C FFI type rules still apply

For things crossing the boundary, stick to C-compatible types.

Good:

```rust
i32
u32
f32
f64

*const T
*mut T

std::ffi::c_int
std::ffi::c_char
std::ffi::c_void
```

For structures:

```rust
#[repr(C)]
pub struct Config {
    pub width: i32,
    pub height: i32,
}
```

Don't directly expose things like:

```rust
String
Vec<T>
&str
&T
Option<T>
```

unless you've specifically established a compatible ABI representation.

For strings, typically:

```rust
*const c_char
```

and `CString`/`CStr` on the Rust side.

# Another improvement: distinguish safe and unsafe functions

I'd consider letting your declaration express this:

```rust
required
unsafe fn initialize(ptr: *mut Config) -> i32;
```

versus:

```rust
fallback(add_fallback)
fn add(a: i32, b: i32) -> i32;
```

Then generate:

```rust
pub unsafe fn initialize(...)
```

for native functions whose caller has to uphold pointer/lifetime invariants.

That's much better than blindly generating a safe Rust method around arbitrary C calls.

For example:

```rust
native_api! {
    pub struct MyStruct(LIB_PATH) {
        required
        unsafe fn process_buffer(
            data: *mut u8,
            len: usize,
        ) -> i32;

        fallback(add_fallback)
        fn add(a: i32, b: i32) -> i32;
    }
}
```

could produce:

```rust
unsafe {
    api.process_buffer(ptr, len);
}

let result = api.add(5, 10);
```

That preserves Rust's safety boundary properly.

# The design I would settle on

I would make the public-facing syntax essentially this:

```rust
const LIB_PATH: &str = "...";

native_api! {
    pub struct MyStruct(LIB_PATH) {
        required
        fn initialize() -> i32;

        required
        fn shutdown() -> i32;

        fallback(calculate_fallback)
        fn calculate(value: i32) -> i32;

        fallback(get_name_fallback)
        unsafe fn get_name(
            buffer: *mut c_char,
            length: usize,
        ) -> i32;
    }
}
```

With these guarantees:

| Declaration      |       Library absent |        Symbol absent | Symbol present |
| ---------------- | -------------------: | -------------------: | -------------: |
| `required fn`    | initialization error | initialization error |         native |
| `fallback(x) fn` |             fallback |             fallback |         native |

And critically:

```rust
let api = MyStruct::new()?;
```

means:

> **Every required piece of `MyStruct` is now valid.**

After initialization there should be no repeated symbol lookup, no repeated DLL checks, and no possibility that a `required` method suddenly isn't available.

That is the architecture I'd use. The original implementation is workable, but **`extern "C"` + non-optional storage for required functions + atomic required-symbol validation + keeping the library alive** are the changes I consider most worthwhile before using this broadly.

# 4. `src/native_api.rs`

````rust
use std::{
    error::Error,
    fmt,
    path::PathBuf,
};

/// Errors that prevent a native API from being constructed.
///
/// A missing library is only an error if the API contains at least
/// one `required` function.
///
/// A missing symbol is only an error if that symbol was declared
/// `required`.
#[derive(Debug)]
pub enum NativeApiError {
    LibraryUnavailable {
        path: PathBuf,
        reason: String,
    },

    MissingRequiredSymbol {
        path: PathBuf,
        symbol: &'static str,
        reason: String,
    },
}

impl fmt::Display for NativeApiError {
    fn fmt(
        &self,
        f: &mut fmt::Formatter<'_>,
    ) -> fmt::Result {
        match self {
            Self::LibraryUnavailable {
                path,
                reason,
            } => {
                write!(
                    f,
                    "native library '{}' could not be loaded: {}",
                    path.display(),
                    reason,
                )
            }

            Self::MissingRequiredSymbol {
                path,
                symbol,
                reason,
            } => {
                write!(
                    f,
                    "required symbol '{}' was not found in '{}': {}",
                    symbol,
                    path.display(),
                    reason,
                )
            }
        }
    }
}

impl Error for NativeApiError {}


/// Declare an API backed by a dynamically loaded C library.
///
/// Syntax:
///
/// ```ignore
/// native_api! {
///     pub struct MyApi(LIBRARY_PATH) {
///         required
///         fn required_function(value: i32) -> i32;
///
///         fallback(my_fallback)
///         fn optional_function(value: i32) -> i32;
///     }
/// }
/// ```
///
/// Semantics:
///
/// required:
///     Library missing -> error
///     Symbol missing  -> error
///     Symbol exists   -> native function
///
/// fallback:
///     Library missing -> fallback
///     Symbol missing  -> fallback
///     Symbol exists   -> native function
///
/// All dynamically loaded functions use the C ABI:
///
///     unsafe extern "C" fn(...)
///
#[macro_export]
macro_rules! native_api {
    (
        $vis:vis struct $struct_name:ident($library_path:expr) {
            $(
                $mode:ident $(($fallback:path))?
                fn $fn_name:ident(
                    $(
                        $arg:ident : $arg_ty:ty
                    ),*
                    $(,)?
                )
                $(-> $ret:ty)?;
            )*
        }
    ) => {
        $vis struct $struct_name {
            /*
             * This MUST remain alive while any of the stored function
             * pointers can be called.
             *
             * If the API is running entirely on fallbacks because the
             * library didn't exist, this is None.
             */
            __library: Option<::libloading::Library>,

            $(
                /*
                 * Required functions are also represented internally
                 * as Option.
                 *
                 * However, new() guarantees they are Some before the
                 * struct can ever be constructed.
                 *
                 * Fallback functions legitimately remain None if their
                 * native symbol wasn't available.
                 */
                $fn_name: Option<
                    unsafe extern "C" fn(
                        $( $arg_ty ),*
                    )
                    $(-> $ret)?
                >,
            )*
        }

        impl $struct_name {
            /// Load the native library and resolve this API.
            ///
            /// If every function is fallback-capable, failure to load
            /// the library is NOT an error.
            ///
            /// If even one function is `required`, failure to load the
            /// library eventually produces an error while resolving that
            /// required function.
            pub fn new(
            ) -> Result<
                Self,
                $crate::native_api::NativeApiError
            > {
                let __path =
                    ::std::path::PathBuf::from($library_path);

                /*
                 * Loading the library itself is intentionally allowed
                 * to fail here.
                 *
                 * Whether that failure matters depends on whether one
                 * of the declarations below is `required`.
                 */
                let (__library, __load_error) =
                    match unsafe {
                        ::libloading::Library::new(&__path)
                    } {
                        Ok(__library) => {
                            (
                                Some(__library),
                                None,
                            )
                        }

                        Err(__error) => {
                            (
                                None,
                                Some(__error.to_string()),
                            )
                        }
                    };

                /*
                 * Resolve every declared symbol exactly once.
                 */
                $(
                    let $fn_name:
                        Option<
                            unsafe extern "C" fn(
                                $( $arg_ty ),*
                            )
                            $(-> $ret)?
                        >
                        =
                        $crate::native_api!(
                            @resolve
                            $mode $(($fallback))?;

                            __library.as_ref();

                            __load_error.as_deref();

                            &__path;

                            stringify!($fn_name);

                            unsafe extern "C" fn(
                                $( $arg_ty ),*
                            )
                            $(-> $ret)?
                        )?;
                )*

                Ok(Self {
                    __library,

                    $(
                        $fn_name,
                    )*
                })
            }

            /// Returns true when the backing DLL/SO was successfully
            /// loaded.
            ///
            /// This does NOT mean every fallback-capable function had
            /// a native implementation.
            pub fn native_library_loaded(
                &self,
            ) -> bool {
                self.__library.is_some()
            }

            /*
             * Generate the public wrapper methods.
             */
            $(
                $crate::native_api!(
                    @method
                    $mode $(($fallback))?

                    fn $fn_name(
                        $(
                            $arg : $arg_ty
                        ),*
                    )
                    $(-> $ret)?;
                );
            )*
        }
    };


    // ========================================================
    // Resolve a REQUIRED function
    // ========================================================

    (
        @resolve
        required;

        $library:expr;

        $load_error:expr;

        $path:expr;

        $symbol_name:expr;

        $fn_type:ty
    ) => {{
        match $library {
            /*
             * The library exists.
             *
             * The symbol MUST also exist.
             */
            Some(__library) => {
                match unsafe {
                    __library.get::<$fn_type>(
                        $symbol_name.as_bytes()
                    )
                } {
                    Ok(__symbol) => {
                        /*
                         * Copy the function pointer out of Symbol.
                         *
                         * The generated struct keeps Library alive,
                         * so this pointer remains valid for the
                         * lifetime of the API object.
                         */
                        Ok(Some(*__symbol))
                    }

                    Err(__error) => {
                        Err(
                            $crate::native_api::NativeApiError::
                                MissingRequiredSymbol {
                                    path:
                                        $path.to_path_buf(),

                                    symbol:
                                        $symbol_name,

                                    reason:
                                        __error.to_string(),
                                }
                        )
                    }
                }
            }

            /*
             * Because this function is required, absence of the
             * entire DLL/SO is an error.
             */
            None => {
                Err(
                    $crate::native_api::NativeApiError::
                        LibraryUnavailable {
                            path:
                                $path.to_path_buf(),

                            reason:
                                $load_error
                                    .unwrap_or(
                                        "unknown library loading error"
                                    )
                                    .to_owned(),
                        }
                )
            }
        }
    }};


    // ========================================================
    // Resolve a FALLBACK-CAPABLE function
    // ========================================================

    (
        @resolve
        fallback($fallback:path);

        $library:expr;

        $load_error:expr;

        $path:expr;

        $symbol_name:expr;

        $fn_type:ty
    ) => {{
        /*
         * These values aren't needed for the fallback case, but are
         * part of the common resolver interface.
         */
        let _ = $load_error;
        let _ = $path;

        match $library {
            /*
             * Library exists.
             *
             * Try to find the native implementation.
             */
            Some(__library) => {
                match unsafe {
                    __library.get::<$fn_type>(
                        $symbol_name.as_bytes()
                    )
                } {
                    /*
                     * Native implementation exists.
                     */
                    Ok(__symbol) => {
                        Ok(Some(*__symbol))
                    }

                    /*
                     * Symbol doesn't exist.
                     *
                     * This is okay because this declaration has a
                     * fallback.
                     */
                    Err(_) => {
                        Ok(None)
                    }
                }
            }

            /*
             * Entire DLL/SO doesn't exist.
             *
             * Also okay because this function has a fallback.
             */
            None => {
                Ok(None)
            }
        }
    }};


    // ========================================================
    // Generate REQUIRED public method
    // ========================================================

    (
        @method
        required

        fn $fn_name:ident(
            $(
                $arg:ident : $arg_ty:ty
            ),*
        )
        $(-> $ret:ty)?;
    ) => {
        pub fn $fn_name(
            &self,
            $(
                $arg : $arg_ty
            ),*
        )
        $(-> $ret)?
        {
            /*
             * This expect cannot fail through normal safe code.
             *
             * new() refuses to construct the API if a required
             * function is absent.
             */
            let __function =
                self
                    .$fn_name
                    .expect(
                        concat!(
                            "internal invariant violated: required ",
                            "native function `",
                            stringify!($fn_name),
                            "` is missing"
                        )
                    );

            unsafe {
                __function(
                    $( $arg ),*
                )
            }
        }
    };


    // ========================================================
    // Generate FALLBACK-CAPABLE public method
    // ========================================================

    (
        @method
        fallback($fallback:path)

        fn $fn_name:ident(
            $(
                $arg:ident : $arg_ty:ty
            ),*
        )
        $(-> $ret:ty)?;
    ) => {
        pub fn $fn_name(
            &self,
            $(
                $arg : $arg_ty
            ),*
        )
        $(-> $ret)?
        {
            match self.$fn_name {
                /*
                 * Prefer the native C implementation whenever it
                 * exists.
                 */
                Some(__function) => {
                    unsafe {
                        __function(
                            $( $arg ),*
                        )
                    }
                }

                /*
                 * Otherwise execute ordinary Rust code.
                 */
                None => {
                    $fallback(
                        $( $arg ),*
                    )
                }
            }
        }
    };
}
````

The crucial piece here is that `Library::get` is unsafe because Rust cannot verify that the requested Rust function-pointer type actually matches the exported native function. That signature correctness is part of your FFI contract. ([Docs.rs][2])

The generated struct also keeps the `Library` alive. `libloading::Symbol` itself is explicitly lifetime-bound to its `Library` to guard against calling into an unloaded library; here we copy the function pointer but preserve the same safety requirement by storing `__library` in the struct. ([Docs.rs][3])

# 5. `src/main.rs`

```rust
mod native_api;

use std::error::Error;


// ============================================================
// Native library location
// ============================================================

#[cfg(target_os = "windows")]
const LIB_PATH: &str =
    r"native\demo.dll";

#[cfg(target_os = "linux")]
const LIB_PATH: &str =
    "native/libdemo.so";

#[cfg(not(any(
    target_os = "windows",
    target_os = "linux"
)))]
compile_error!(
    "This demo currently defines a library path only for Windows and Linux."
);


// ============================================================
// Rust fallback implementations
// ============================================================

fn fallback_multiply(
    a: i32,
    b: i32,
) -> i32 {
    println!(
        "[Rust fallback] optional_multiply()"
    );

    a * b
}


fn fallback_subtract(
    a: i32,
    b: i32,
) -> i32 {
    println!(
        "[Rust fallback] optional_subtract()"
    );

    a - b
}


// ============================================================
// Mixed API
//
// Because this API contains `required_add`, the DLL/SO itself
// becomes required.
//
// DLL/SO missing:
//     MixedApi::new() -> Err
//
// required_add missing:
//     MixedApi::new() -> Err
//
// optional_multiply missing:
//     fallback_multiply()
//
// optional_subtract missing:
//     fallback_subtract()
// ============================================================

native_api! {
    pub struct MixedApi(LIB_PATH) {
        required
        fn required_add(
            a: i32,
            b: i32,
        ) -> i32;

        fallback(fallback_multiply)
        fn optional_multiply(
            a: i32,
            b: i32,
        ) -> i32;

        fallback(fallback_subtract)
        fn optional_subtract(
            a: i32,
            b: i32,
        ) -> i32;
    }
}


// ============================================================
// Fallback-only API
//
// Because NOTHING in this API is required, the entire API can
// be constructed even when the DLL/SO doesn't exist.
//
// DLL/SO exists:
//     use native symbols where available
//
// DLL/SO missing:
//     use every fallback
// ============================================================

native_api! {
    pub struct FallbackOnlyApi(LIB_PATH) {
        fallback(fallback_multiply)
        fn optional_multiply(
            a: i32,
            b: i32,
        ) -> i32;

        fallback(fallback_subtract)
        fn optional_subtract(
            a: i32,
            b: i32,
        ) -> i32;
    }
}


// ============================================================
// Main
// ============================================================

fn main() -> Result<(), Box<dyn Error>> {
    println!("==============================");
    println!("Mixed API");
    println!("==============================");

    match MixedApi::new() {
        Ok(api) => {
            println!(
                "Native library loaded: {}",
                api.native_library_loaded()
            );

            /*
             * REQUIRED:
             *
             * If we got this far, required_add definitely exists.
             */
            let result =
                api.required_add(
                    10,
                    5,
                );

            println!(
                "required_add(10, 5) = {result}"
            );


            /*
             * FALLBACK-CAPABLE:
             *
             * optional_multiply exists in demo.c, so the C
             * implementation should execute.
             */
            let result =
                api.optional_multiply(
                    10,
                    5,
                );

            println!(
                "optional_multiply(10, 5) = {result}"
            );


            /*
             * FALLBACK-CAPABLE:
             *
             * optional_subtract does NOT exist in demo.c, so
             * fallback_subtract() should execute.
             */
            let result =
                api.optional_subtract(
                    10,
                    5,
                );

            println!(
                "optional_subtract(10, 5) = {result}"
            );
        }

        Err(error) => {
            println!(
                "MixedApi could not be initialized:"
            );

            println!(
                "    {error}"
            );
        }
    }


    println!();
    println!("==============================");
    println!("Fallback-only API");
    println!("==============================");

    /*
     * This succeeds EVEN IF demo.dll / libdemo.so is completely
     * absent because this API contains no required functions.
     */
    let api =
        FallbackOnlyApi::new()?;

    println!(
        "Native library loaded: {}",
        api.native_library_loaded()
    );


    let result =
        api.optional_multiply(
            6,
            7,
        );

    println!(
        "optional_multiply(6, 7) = {result}"
    );


    let result =
        api.optional_subtract(
            10,
            3,
        );

    println!(
        "optional_subtract(10, 3) = {result}"
    );


    Ok(())
}
```

## The resulting rules

| Declaration            | DLL/SO missing | Symbol missing | Symbol exists |
| ---------------------- | -------------- | -------------- | ------------- |
| `required fn foo()`    | `new()` errors | `new()` errors | C function    |
| `fallback(x) fn foo()` | Rust fallback  | Rust fallback  | C function    |

And when mixed:

```rust
native_api! {
    pub struct Foo(LIB_PATH) {
        required
        fn one();

        fallback(two_fallback)
        fn two();
    }
}
```

the presence of:

```rust
required
fn one();
```

means:

```text
Foo requires the DLL/SO to exist.
```

Even though `two()` has a fallback.

## One safety limitation I would keep very explicit

This:

```rust
required
fn required_add(
    a: i32,
    b: i32,
) -> i32;
```

is effectively you asserting that the C declaration really is:

```c
int32_t required_add(
    int32_t a,
    int32_t b
);
```

`libloading` cannot inspect a C export and determine its actual parameter or return types; `Library::get` therefore requires an unsafe operation and the caller is responsible for providing the correct type. ([Docs.rs][2])

If you accidentally write:

```rust
required
fn required_add(
    value: f64,
) -> *mut u8;
```

while the C function is:

```c
int32_t required_add(
    int32_t a,
    int32_t b
);
```

symbol lookup can still succeed because the exported **name** exists, but actually calling it can be undefined behavior.

For your use case—**your own C projects with controlled headers**—that is a reasonable contract.

### One thing I'd add next

If these APIs will ever contain raw pointers such as:

```rust
fn process(
    buffer: *mut u8,
    length: usize,
);
```

I would extend the macro syntax to support:

```rust
required
unsafe fn process(
    buffer: *mut u8,
    length: usize,
);
```

and:

```rust
fallback(process_fallback)
unsafe fn process(
    buffer: *mut u8,
    length: usize,
);
```

so that the generated Rust API does not accidentally turn arbitrary pointer-based C operations into safe Rust functions.

For functions like:

```rust
i32 -> i32
i32, i32 -> i32
f64 -> f64
```

where every possible input is legitimate from the C function's perspective, the version above is a good compact baseline.
